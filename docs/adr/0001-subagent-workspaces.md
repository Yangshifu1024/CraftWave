# 写入子代理使用独立工作区，公共操作由主代理统一执行

M2 采用独立 Git worktree 隔离写入子代理，避免多个代理直接修改同一工作副本；相比仅在共享目录上认领文件，这需要额外管理工作区起点与结果回收，但能让子代理各自编辑和运行局部测试。只读探索与评审继续读取当前工作区；非 Git 项目暂由主代理修改，子代理只读。

worktree 无法隔离数据库、外部服务等共享资源。公共操作仅由主代理在相关子代理完成并收齐改动后执行，工具权限入口负责落实该角色限制。

子代理从派发时当前文件状态开始，包括未提交修改与未被忽略的新文件，后续不自动同步。主代理按相对派发起点的差量汇回当前工作区；冲突时保留双方内容并解决验证，保留用户已有修改。创建和回收均不自动 commit/push，不改变用户已有暂存状态。

失败或取消的未汇回工作区保留供检查和回收，重启不自动续跑；成功汇回并验证后才清理。工作区按项目现有方式准备依赖，本地配置缺失交主代理协调，不批量复制主工作区忽略文件。

M2 仅主代理可委派子代理，子代理进一步拆分任务时交回主代理协调，避免嵌套等待占满并发名额。子代理并发限制跨会话共用，默认 4，用户可在设置页修改并持久化。

决策依据：2026-10-29 M2 grilling，用户提出 worktree 方向并确认 Q7–Q13。实现要求见 M2 10 号票与技术设计 §5.9。
