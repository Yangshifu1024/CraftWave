### 1.4 术语表

| 术语 | 定义 |
|---|---|
| Agentic Loop | 模型→工具调用→结果回喂→再决策的多轮自动循环 |
| BYOK | Bring Your Own Key，用户自带模型 API Key |
| HITL | Human-In-The-Loop，人工介入（审批、回答提问） |
| TOFU | Trust On First Use，首次使用信任决策（MCP server 启动、项目资源加载） |
| MCP | Model Context Protocol，模型上下文协议（外挂工具/资源标准） |
| Compaction | 上下文压缩：将冗长历史摘要化以释放上下文窗口 |
| Steer | 运行中注入消息且不终止当前 run 的"转向"语义 |
| Follow-up | 运行中排队、待当前 run 完成后自动投递的消息 |
| Roots | Agent 文件操作允许的根目录集合（项目主目录 + 已授权外部目录） |
| Channel 帧 | Tauri `ipc::Channel` 传递的高频流式帧（文本增量、工具进度等） |
| 事件 | Tauri `emit_to` 传递的低频具名状态事件（run 终态、审批开启等） |
| Run | 用户一次发送到 Agent 回答完毕（含全部工具轮）的完整执行 |
| 权限档 | 会话级权限模式（plan / confirm_each / auto_edit / full_access） |

## 2. 产品概述

### 2.1 产品定位

**CraftWave 是一款本地优先、隐私优先、BYOK 的跨平台（macOS / Windows / Linux）桌面 AI Agent**：以对话驱动 Agent 在本机项目中读代码、改文件、跑命令、查资料、管理任务；同时具备通用桌面助手能力（文档处理、信息检索、自动化）。所有数据默认仅存本地，默认零遥测。

产品形态为单一原生桌面应用（Tauri 2），无账号体系、无强制登录、无云端依赖。

### 2.2 目标用户与核心场景

**目标用户**：开发者（主力）、重度技术用户（脚本/数据/办公自动化）。

**核心场景**（User Journey）：

1. **日常编码**：打开项目 → 描述需求 → Agent 探索代码 → 出计划 → 批准 → 修改多文件 → 跑测试 → 汇报。全程可见 diff，写操作按权限档确认。
2. **调试排障**：粘贴报错/截图 → Agent 复现、定位、修复 → 展示修改与验证结果。
3. **代码理解与审查**：指定目录或模块 → Agent 生成架构说明/审查报告（markdown 渲染）。
4. **项目脚手架**：从一句话需求生成可运行项目骨架（含预览 HTML 组件）。
5. **文档与办公**：读写 xlsx/docx/pdf，批量整理数据，生成报告。
6. **信息检索**：web_fetch/web_search 工具查资料并汇总（带来源）。
7. **自动化例行事**：定时任务（cron/interval）自动执行检查、汇报（P2）。
8. **通用问答**：临时会话免选目录直接开聊，作为日常 AI 助手。
9. **后台长任务**：委派长任务后关闭/最小化窗口照常执行；任务完成或需要审批/回答时收到系统通知，点击通知直达对应会话继续处理。

### 2.3 设计原则

1. **本地优先**：会话、配置、密钥、记忆全部留在本机；默认零遥测，任何上报必须显式开关。
2. **BYOK、不锁定**：多供应商 + 自定义 OpenAI 兼容端点；密钥进系统钥匙串，永不明文落盘为设计目标。
3. **分级安全、用户主权**：权限档位 + 审批门 + 命令围栏 + 路径边界；用户始终拥有最终控制权；灾难级操作永不自动放行。
4. **可审计**：append-only 会话历史、run 级日志、事件对账自愈；任何 Agent 行为可回溯。
5. **单进程简单性**：Tauri 2 单进程 + 进程内 rig 内核（对比 metis 的 Electron + Node server 子进程双进程模型），换取体积、内存、分发与安全面优势。
6. **组合优于自研**：LLM 接入用 rig、聊天 UI 用 assistant-ui，自研工程集中投入产品差异层（安全、编排、桌面体验）。

### 2.4 对标分析与差异化

#### 2.4.1 与 CodeWave 的关系：代际重铸

CodeWave 为同作者上一代产品，其经过大量真实使用验证的机制**直接继承**，同时做三处代际升级：

| 维度 | CodeWave 0.14（现状） | CraftWave（本产品） |
|---|---|---|
| LLM 接入层 | 手写三协议（openai_chat/anthropic_messages/openai_responses）+ SSE + 重试 + Key 池，约 5000 行 | **rig** 进程内嵌：27 provider 模块 + 19 OpenAI 兼容方言 + 流式/重试/工具调用内置；自研收缩为适配与增强层（Key 池、缓存断点等协议细节） |
| 聊天 UI | antd 自研约 1 万行；**无消息分支/编辑/重生成** | **assistant-ui**：LocalRuntime 内置消息树、分支切换、编辑重发、重生成；Headless 原语 + 组件库；HITL 审批卡/human tool 生态 |
| 知识检索 | 无 RAG（grep + 记忆文件） | 增加**本地 RAG**（rig + sqlite-vec + fastembed，完全离线） |
| 继承保留 | — | 四档权限、命令围栏（AST 路线）、append-only 分段历史、事件契约测试、终态对账自愈、steer 注入、MCP TOFU、keyring 凭据提交协议、UI 现场恢复 |
| 补足短板 | 无分支/编辑、无导出、无虚拟滚动、无成本统计 | 全部纳入需求（FR-01/FR-02/FR-15） |

#### 2.4.2 与 metis 的差异化

| 维度 | metis 2.0（Electron） | CraftWave（Tauri 2） |
|---|---|---|
| 运行形态 | Electron + `metis server` Node 子进程（HTTP+SSE :4096） | 单进程，rig 编入 Rust 核心，IPC 直连 |
| 安装包/内存 | 需专门瘦身脚本，捆绑 Node/ffmpeg/onnxruntime | Tauri 系统 webview，天然轻量 |
| MCP | 无（以 TS 扩展 + Skills 替代） | **内建 MCP 客户端**（rig-rmcp，stdio + streamable HTTP） |
| 桌面集成 | 无托盘/热键/通知/多窗口；无 Linux 包 | 托盘、全局热键、系统通知、三平台 |
| 消息分支 | JSONL 树 + `/fork`、`/tree`（CLI 交互） | assistant-ui 原生分支 UI（BranchPicker/编辑/重生成） |
| 借鉴吸收 | — | 任务分级与质量门思想（FR-06）、steer/followUp 双语义队列（FR-01/FR-03）、角色分工子代理（FR-07）、项目级 Agent 架构定制（FR-06，P3）、自我学习的工程护栏思想（FR-09，P3） |

#### 2.4.3 竞争位次总结

CraftWave 的差异化配方 = **CodeWave 的安全与可靠性工程** + **metis 的编排产品学** + **rig/assistant-ui 的现代技术栈红利**（分支能力、RAG、MCP、轻量分发）。

### 3.3 前后端通信契约（架构需求）

**三通道**（继承 CodeWave 已验证模式）：

1. **invoke 命令**（请求-响应）：配置、会话管理、MCP、项目、统计等约 60~120 个命令，按域分模块注册；前端唯一入口 `ipc/client.ts`，契约类型 `ipc/types.ts` 双端共享。
2. **ipc::Channel 高频帧**（点对点有序）：`Frame::Text{delta}` / `Frame::Reasoning{delta}` / `Frame::StepStart` / `Frame::ToolStart{id}` / `Frame::ToolProgress{id}` / `Frame::ToolResult{id}` / `Frame::Usage` / `Frame::Sub{sub_id, frame}`；64ms 节流合并。
3. **emit_to 低频事件**（具名、固定键面）：`run:start/done/error/cancelled/retry/inject`、`tool:start/result/error`、`plan:update`、`tokens:update`、`ask:opened/closed`、`sub:*`、`mcp:status`、`session:title`、`notify:activate`、`app:exit_requested` 等（初版 ≤ 30 键，见附录 D）。

**映射链（关键）**：rig `MultiTurnStreamItem`（StreamAssistantItem 文本/推理/工具参数增量、ToolCall/ToolResult、FinalResponse）→ Rust 转换为 Channel 帧 → 前端 `ChatModelAdapter` 内累积为 assistant-ui 消息 part（text / reasoning / tool-call）。

**契约防漂移**：必须有**事件契约测试**——双向扫描 Rust `emit`/帧 枚举与前端 handler 绑定，键面硬锚点（继承 CodeWave 已验证的契约测试模式，对应 NFR-12）。

**终态对账**：事件可能丢失，run 终态必须可经 `session_run_snapshot` 命令快照对账自愈（对应 FR-03-08）。

### 3.4 数据存储设计

- **双作用域**：全局 `~/.craftwave/`（config.json、projects/、sessions/、histories/、mcp.json、skills/、memories/、stats/、logs/、trust/）与项目 `<主目录>/.craftwave/`（project.json、skills/、memory/、mcp.json、tasks/），**项目数据随项目走**（继承 CodeWave）。
- **会话历史 append-only 分段 JSONL（真相层核心）**：日志引擎采用 rig-memory `rig-session/4` 格式（自带 append 乐观并发、resume/rewrite/fork、格式迁移保旧副本），其上叠加产品语义——分段封口（200 条或 512KB，绝不切在 tool_call/tool_result 配对中间）、前缀指纹不匹配只新增段绝不覆盖、软告警/硬熔断只停写不删数据（继承 CodeWave）。
- **消息树与 assistant-ui 对齐**：持久化格式需保留 parentId 结构（支持分支），与 assistant-ui `ExportedMessageRepository` 互转（对应 D8，详细设计另出）。
- **原子写**：全部配置/索引经 tempfile + rename 原子替换（Windows MoveFileExW）；锁序纪律统一。
- **图片外置内容寻址 blob**（SHA-256 前 32 hex 去重）；**工具结果完整边车**（键 = provider 侧 tool_call id，用于 UI 恢复，不计费不进上下文）。
- **派生索引层（SQLite，`cache/index.db`）**：与真相层分离的第二层存储，仅存可重建数据——会话列表加速、FTS5 跨会话全文、统计聚合缓存、（P2）sqlite-vec RAG 向量；受三铁律约束（唯一数据只在文件 / 可随时删除并自动重建 / 不入云同步目录），降级与重建协议见《数据存储调研.md》§5.3（对应 D7、NFR-21、FR-14-09）。

### 3.5 rig 集成方式

- **crate 组合**：`rig-core` + `rig-agent` + `rig-reqwest` + `rig-rmcp`（facade feature：`rig = { features = ["derive", "rmcp", ...] }`）；P2 增加 `rig-sqlite` + `rig-fastembed`（本地 RAG）。
- **进程内嵌，不用 sidecar/本地 HTTP server**：rig 无 server 能力也不需要——Tauri IPC 即是边界（决策 D1/D3）。
- **运行编排**：`AgentBuilder` 构建（preamble 分层、工具注册、memory）→ `agent.prompt(msg).history(h).max_turns(n).tool_concurrency(k)` → `run_channel()` 获得 future + `RunEvents` 通道 → Tauri 命令内消费并转发为 Channel 帧/事件。
- **HITL**：`AgentHook::Dispatch`（Proceed/skip/rewrite_tool_args/stop）实现审批门与 human tool（对接 assistant-ui approval / requires-action）。
- **取消**：Tauri 侧 CancellationToken 映射 rig 取消；`abortSignal` → `invoke("cancel_run")`。
- **会话恢复**：`AgentRun` 可序列化状态用于崩溃恢复与跨进程审批（P2 深化）。
- **需要自研补齐的协议细节**（CodeWave 踩坑结晶，rig 不完全覆盖）：多 Key 池轮换冷却、Anthropic prompt 缓存断点策略、`reasoning_content` 回传粘性、空响应诊断、BadRequest sanitize 修复重试。

### 3.6 assistant-ui 集成方式

- **Runtime**：`useLocalRuntime(tauriChatModel)` + `ChatModelAdapter`：`run(options)` 内 `invoke("start_chat", { messages, tools, runConfig })`，通过 `ipc::Channel` 收帧，累积后 yield（assistant-ui 要求 yield 累计全文而非增量）；`abortSignal` → `invoke("cancel_run")`。此为官方 Tauri 指南路径。
- **工具 UI**：`defineToolkit({ name: { description, parameters, render } })` + `AuiConfig({ tools })`；每类工具卡片（文件 diff、命令输出、检索结果…）以 render 函数定制；无自定义 UI 的工具走 ToolFallback。
- **HITL**：审批门用 tool-call part `approval` + `respondToApproval`；用户供数工具用 human tool / requires-action 状态 + `unstable_humanToolNames`。
- **分支/编辑/重生成**：LocalRuntime 内置，无需自研（相对 CodeWave 的核心增益）。
- **组件获取**：`npx assistant-ui@latest add thread` 等（shadcn registry copy-paste 模式），基于 Tailwind v4 + Base UI。
- **长会话**：虚拟滚动参考 `with-virtualized-thread` 模式（TanStack Virtual）。
- **安全注意**（官方指南要求）：CSP `connect-src ipc: http://ipc.localhost`；capabilities 最小化；API Key 只存 Rust 侧，不进前端与 `VITE_*`。
