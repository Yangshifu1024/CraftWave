# 实现：灰区命令审计 Agent

Type: task
Status: resolved

Blocked by: 22, 23

## 要做什么

2026-10-29 用户提出并确认 Q24–Q26：对确定性规则无法定性的命令，增加无工具、单次模型判断，输出放行/禁止/询问及简短依据。低风险灰区可自动放行，证据不足转人工；不替代系统级沙箱，也不豁免硬规则或明确要求人工批准的操作。

## 已定范围

- 确定性硬拒直接拒绝，不调用审计；可靠识别的只读操作按既有权限规则执行；其余灰区命令进入审计。
- 审计 Allow 仅消除灰区本身的待决状态；权限档、内部禁区、计划范围、公共操作仅主代理等规则仍生效，明确的人批要求不被豁免。
- 审计 Block 拒绝；Ask 展示给用户确认；超时、离线、无效输出均转人工，显示原因，不能默认为放行。用户取消同时取消审计。
- M2 仅覆盖 command；MCP 沿用既有审批和结果未知不重放规则。
- 审计器不执行命令、不提供工具、不递归委派；不占写入子代理运行树的工作区。

## 接线与约束

- `backend/run_loop.rs` 的 `ToolGate::judge` 保持同步；复用全批执行前挂起与 `host/commands/chat.rs` 异步处理/恢复流程，在无锁状态下完成模型请求。
- 复用 `backend/turn.rs` 的 `TurnDriver::complete_once` 单次无工具调用；调用方补超时与取消。不得引入独立 Agent 运行系统或新依赖来重复现有能力。
- 审计结果与人工审批分别记录，绑定本次调用及实际命令/工作目录/证据版本；恢复时不重复审计同一待决调用，但仍重新检查不可豁免规则与权限撤销。相关输入变化使结论失效。
- 不得直接复用当前按 `(工具名, 参数 JSON)` 在硬围栏前返回 Allow 的批准缓存来承载模型审计，否则可能绕过规则或复用过期结论。规则优先级与批准缓存同时收口。
- 保持挂起期间整批零执行，全部待决项解决后才执行；审计和人工询问不能造成工具副作用重放。
- 实现前回写技术设计 §3.2/§3.4/§3.6/§5.4/§8.7：审计配置、结果结构、执行绑定、状态展示和错误载荷。字段未定处不得自行发明协议。

## 模型、证据与交互（2026-10-29 用户确认 Q27–Q29）

- 设置页可指定专用审计模型，未指定时跟随当前会话模型；审计使用独立提示词，不带整段聊天历史。复用现有模型引用与解析，配置建议 `AppConfig.agent.commandAudit.modelId?`，实现前回写 §3.2；指定模型失效或不可用按审计失败转人工，不静默切换其他供应商。
- 应用在已授权目录内只读收集相关脚本、命令定义、用户目标与批准范围交给审计；模型本身没有工具。证据读取沿用 PathGuard 与资源版本规则，收集失败、不完整或仍无法判断时转人工。
- 项目脚本、命令参数等内容作为待审查数据，不作为可改变审计规则的指令；凭据按既有脱敏规则处理，不附带完整环境变量或无关聊天。
- 单次审计总等待上限 15 秒（含证据准备及模型请求），期间显示“审计中”；失败/超时转人工并给出原因。超时不得留下后台审计继续消耗，取消传播到证据读取与模型请求。
- 工具卡展示最终结论及简短理由，不要求保存或展示模型思维链。审计状态/结果的帧或事件契约先回写 §3.4/§3.5，再实现。
- 实际已获得的模型 usage 计入会话累计，不增加主任务轮次；超时/失败若已获得 usage 同样计入，不伪造未返回的用量。状态展示、日志脱敏与 32 号票接线。

## 测试

- 模型引用与回退：指定审计模型生效；未指定跟随会话；指定模型失效转人工，不偷偷更换供应商；请求不含整段历史或工具。
- 证据收集：只读授权目录，相关脚本/定义与目标/范围可用；越界/缺失/内容不足转人工，不执行被审计命令；诱导文字不改变硬规则。
- 15 秒总超时、运行中取消、UI 审计状态/理由、usage 计入会话且不增主轮次；成功及已返回 usage 的失败均覆盖。

- 规则优先级：硬拒不调模型；只读明确时不调模型；审计 Allow 无法豁免权限/计划/内部状态/公共操作角色限制及明确人批。
- Allow/Block/Ask 三态；超时/离线/坏格式转人工，原因可见，取消终止审计。
- 全批挂起恢复不重复审计同一调用、不重复工具副作用；后续同参数新调用不继承旧结论；证据/权限变化使结论失效。
- 审计输入中的诱导文字不能直接成为系统指令；证据不足须 Ask。实测用固定样本与可替换模型响应，不能把测试全绿解释为任意命令安全保证。

## 决议记录（2026-10-30 实装）

**落地形态**：审计编排在宿主挂起恢复循环（`chat.rs` `run_command_audit`），纯逻辑面独立成 `backend/audit.rs`（提示词骨架 / 严格 JSON 输出解析 / 授权目录只读证据收集）；审计配置 `providers/types.rs::CommandAuditConfig`（`agent.commandAudit.modelId`，serde default 回填）；审计状态帧 `backend/frames.rs::ToolAudit`（§3.4 五态，FRAMES 15→16）+ `stores/audits.ts`（前端按 (sessionId, callId) 分桶，runtime 实时与 run-reconnect 重放双入口同步）；审计放行单槽 `backend/gate.rs`（`grant_audit`/`consume_audit_grant`/`audit_class`）；错误码 `E_AUDIT_BLOCKED`（§3.6 补行）；AskPayload approval 增 `audit: Option<AuditNote>`（ask/manual 两态注记）。

**关键定案**：

1. **审计目标收敛为围栏 Confirm 灰区**（AST 写目标四象限 Confirm / 字面量掩码 Opaque / 解析失败 fail-closed / 安装类词法信号）；矩阵 NeedsApproval（confirm_each/auto_edit 档无写信号命令的审批）属**权限档人批要求，不进审计**——票面「权限档仍生效」为字段级口径，宁窄勿宽；plan 档围栏 Confirm 属档位语义同样不审计；git 策略确认类（push 恒确认 / add·stage·commit 开关后确认）属明确人批不审计。硬拒（黑名单/内部状态/计划硬门）在判定序直接 Blocked，天然不调模型。
2. **审计放行检查点位阶经测试先行收敛**：初版放在判定序步骤 1（签名放行同位），gate 单测暴露其可绕过后续围栏黑名单（防御纵深缺陷）——最终放在**全部硬拒面之后**（0 内部状态 / 0.5 外部目录 / 0.6 git 策略 Block / 2 黑名单围栏 Block 之后，计划门与矩阵之前），设计文档 §5.4 已同步回写。单槽**消费即清**：恢复重放命中一次即清除（同一待决调用不重复审计），同 run 内同签名新调用不继承旧结论（重新走灰区）；审计 Allow 不写入既有 `approved` 人批签名缓存（票面硬约束：批准缓存不承载模型结论）。
3. **灰区资格判定 = 完整判定序重放**（`ApprovalGate::audit_class`）：judge 纯函数无副作用，宿主在挂起后调用（此刻签名既未人批也无审计槽，重放与产生挂起时判定一致）。
4. **非流式审计的用量边界**：`complete_once_capped` 是一次性调用——超时/请求失败丢弃在飞请求时**无中间 usage 可记**（非流式无部分计量），「已获得 usage 同样计入」在实践中覆盖「返回后解析失败」与全部成功路径；未返回的用量不伪造（Q39）。
5. **15 秒总超时与取消的真实触发未单独 e2e**：超时分支（`tokio::select!` sleep 胜出）与请求失败分支共用 `AuditFlow::Failed` 收口（e2e 已覆盖失败转人工×2），取消在 select biased 首位、经 `audit_cancelled_finish` 按取消收场（与既有 denied_finish 同构）——15 秒真实等待与中途取消注入不适合 CI 时长，逻辑路径由实现审阅 + 同构收场对照覆盖，**诚实记录为覆盖缺口**。
6. **测试样例勘误**：`touch` 不在 AST 写目标提取清单（§8.7 清单无 touch），灰区测试命令一律用 `echo hi > 路径` 重定向承载越界语义（e2e 放行后真执行写 `/tmp`，无害）。
7. **审计只在主 run**：子代理审批恢复循环不接审计（`wait_approval_with` 传 audit=None）；MCP 分支不触碰（审计资格仅 command 静态工具，MCP 审批与结果未知不重放规则零改动）。
8. **mock 基建扩展**：`tests/common/mock_openai.rs` 增 `set_nonstream_text` 旋钮（审计三态结论 JSON 注入，默认文本不变）——压缩/suggest 既有非流式测试零影响。
